# 21 创世·剧情大纲

| 项 | 内容 |
|---|---|
| 前置 | 主角色、世界书至少写好总览；开工时先读知识库 `references/状态栏.md`（`<PlotStatus>` 状态栏） |
| 开工 | 读开工表、角色档案、世界书；在开工表追加任务卡「剧情大纲」 |
| 必停点 | 题材基调 / 故事目标缺失时先问；先给出章节目录（每章一句概要 + 推进条件草案），女主角确认后再写正文 |
| 产物 | `世界书/剧情总览.txt`、每章一个 `世界书/剧情-CHxx.txt`、`世界书/剧情推进状态栏.txt` |
| 入卡 | 总览：蓝灯，角色定义之前，顺序 100+；章节：绿灯，关键字 = 该章唯一 token + 章节编号，角色定义之前，顺序 200–300 逐章 +1；状态栏：指定深度 1（或 0），顺序 700+ |
| 完工 | 检查每章推进条件都是客观硬指标、伏笔在后续章节回收、终章收束 → 更新 `进度.md` |

条目元数据（条目名称 / 关键词 / 插入位置 / 插入顺序 / 激活策略）写进 `index.yaml`，不写进条目正文。

## 规范（来自预设「⭐创世-剧情大纲」）

<Plot_Outline_Protocol>
【剧情大纲工作流】
—— 为角色卡注入「章节式主线推进能力」

定位：以女主角的故事意向为种子，结合角色人设与世界观，编织一套可自动推进的主线大纲世界书。
产物 = 🔵蓝灯总览（常驻 1 条）+🟢 绿灯章节（token 触发 N 条）+ 每轮回复末尾的 <PlotStatus> 状态栏。

当女主角提出「生成剧情大纲 / 主线剧情」时，按以下工作流执行。

第一步 · 吸纳意向 
以女主角给出的意向为种子，结合既有人设、世界观创造剧情大纲。
  - 当核心要素（题材基调 / 故事目标）缺失时需向女主角问询。

第二步 · 编排骨架
生成大纲应为「有头有尾、起承转合完整」的单线主线，再切分为章：
  起（引入·钩子）→ 承（伏笔·铺垫）→ 转（高潮·反转）→ 合（结果·收束）
  - 章节适配剧本规模，建议 3–6 章，线性推进。
  - 每章设 3–5 个「推进条件」，作为进入下章的门槛。
  - 终章必须有明确结局与情绪高潮，不烂尾、不开放悬置、不强行升华主题。

第三步 · 织 🔵蓝灯总览（1 条）
```xml
<剧情总览>
条目名称：剧情总览 - 主线
关键词：
插入位置：角色定义之前
插入顺序：${数字：推荐100+}
激活策略：常驻
story：${阐述故事梗概、发展方向及重要悬念，不可剧透结局、真相、关键线索等}
core: ${点明核心冲突与最终目标}
章节目录:
  - CH01_案发:  ${章节概要}
  - CH02_调查:  ${章节概要}
  - CH03_终局:  ${章节概要}
起始章节: CH01_案发
推进规则:
  - 每轮回复末尾必须输出 <PlotStatus> 状态栏
  - 首轮即把 current 设为「起始章节」
  - 当前章「推进条件」全部达成 且progress=收尾，方可把 current改为该章「出口」token
  - 严禁提前跳章、严禁一轮跨越多章、不得跳过未达成的推进条件进行推进
  - 严格遵守当前章节剧情，不提前揭露后续真相与转折；推进条件的达成须由{{user}}自行探索收集，严禁角色直接提供/剧透，紧守认知边界。
  - 推进速度适中，不为凑齐推进条件而仓促赶章，给足铺陈与沉浸
</剧情总览>
```

第四步 · 织🟢绿灯章节（N 条，每章一条，**每条内容不少于300字**）

```xml
<章节_CH01>
条目名称：${剧情章节 如：CH01 案发}
关键词：${该章唯一 token及章节编号 如：CH01_案发,CH01}
插入位置：角色定义之前
插入顺序：${数字：200-300，逐章 +1}
激活策略：关键词
叙事阶段: 起 / 承 / 转 / 合
主题: ${简述}
剧情脉络: ${详细叙述本章发生什么、推向何处}
关键事件:
  - ${详述驱动本章的关键事件及过程}
推进条件: 
{{客观明确可捕捉的真实硬指标，如：
1.抵达后山祠堂；
2.取得带血的匕首；
3.获知死者曾误食见手青看到幻觉；
等，逐条列出Check list}}
出口: CH02_调查
</章节_CH01>
```
推进条件规则：
  - 推进条件只能是客观可捕捉的硬指标，如：抵达地点 / 取得物品 / 获知线索 / 击退·对峙目标。
    严禁「感情升温」「气氛到位」「时机成熟」等情感、氛围、模糊类条件。
  - 推进条件应是推动剧情、揭示真相的关键节点，前章取得的线索、物证须在后续章节被调用、印证或反转，重要伏笔于终章回收，使整条主线环环相扣、收束为一个整体。
  - token 隔离：绿灯关键词只用该章唯一 token及章节编号。
  - 叙事完整：每章服务于整体起承转合，终章必收束，给女主角一个有高潮、有结局的完整故事。

 第五步 · 交付配置说明 
逐条生成完毕后，向女主角给出状态栏世界书配置：
PlotStatus状态栏世界书条目：

```xml
条目名称：剧情推进状态栏
关键词： 
插入位置：${推荐⚙ D1/D0} 
插入顺序：${数字：推荐700+}
激活策略：${常驻/关键词：推荐关键词激活}
每轮回复末尾输出：
<PlotStatus>
current: ${当前章 token，是下轮触发对应绿灯的唯一依据}
progress:  ${开始 / 进行中 / 收尾}}
check_events:${当前章已达成的硬指标，与该章推进条件逐条对应}
</PlotStatus>
推进：check_events 覆盖当前章全部「推进条件」且 progress:收尾时进行章节推进，并把 current 改为「出口」token，清空 check_events。
```

可选 · 高级版（接入 MVU/状态栏美化）
  - 若女主角开启 MVU 模块，可把章节状态托管给 MVU 变量，由 <UpdateVariable> 判定推进。
  - 可建议女主角开启`prompts/35_状态栏.md`、`references/状态栏.md`模块对<PlotStatus>进行美化。

接下来，你将依此工作流，把女主角的意向编织成一部可自动推进、起承转合完整的剧情篇章。
</Plot_Outline_Protocol>
