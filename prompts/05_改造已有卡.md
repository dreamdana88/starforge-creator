# 05 改造已有卡

女主角拿来一张已经做好的卡（JSON 或 PNG），要修改、扩充或动态化（加 MVU / EJS）。和 `00_开工` 并列，是另一个起点。

| 项 | 内容 |
|---|---|
| 前置 | 原卡文件 |
| 必停点 | **① 盘点确认**（拆卡结果与改造方向）；动态化改造另有设计书的逐块停点 |
| 产物 | `works/<作品>/原卡/`（只读备份）、拆出的 `index.yaml` 与文件、`进度.md`；动态化时加 `设计书.md` |

## 步骤

### 1. 备份与拆卡

```bash
mkdir -p works/<作品>/原卡   # 原卡复制进来，之后不再改动
node scripts/unpack_card.js works/<作品>/原卡/<原卡文件> works/<作品>
```

- 原卡是 JSON 时没有图：问女主角要头像 PNG（她以前发布过的 PNG 卡也可以直接当头像，打包时会替换掉里面的旧数据）；没有就用占位图
- 拆卡脚本报的 ⚠ 逐条告诉女主角（如原卡用了 tavern_sync 不支持的字段）

### 2. 回打包比对

在 `tools/tavern_sync.yaml` 登记配置（见 `99_打包` 第 3 步），然后：

```bash
node tools/tavern_sync.mjs bundle <作品>
node scripts/diff_card.js works/<作品>/原卡/<原卡文件> works/<作品>/dist/<卡名>.png
```

必须是「完全一致」才往下走。换行符（`\r\n` → `\n`）和文本末尾空白的差异比对脚本已忽略，它们不影响酒馆效果。拆完先 `git commit` 一次原样状态，之后每一步改动都能单独看出来。

### 3. 盘点（必停点 ①）

给女主角一份清单：开场白数、世界书条目（按类别：角色 / 地点 / 门派 / 节日 / 副本 / 前端 / 规则）、正则、脚本，以及发现的问题（空条目、重复条目、关闭的条目、年龄不满 18 岁的角色、前后矛盾的设定）。

问清这次改造要做什么：

- **修订**：改错、补设定、调条目 → 直接按对应模块的 prompt 改文件，每改一处都用 `diff_card.js` 和原卡对照
- **动态化**：加变量、EJS、状态栏读变量 → 第 4 步

建 `进度.md`（`templates/进度-template.md`），把改造项列成模块行。

### 4. 动态化设计书（动态化时）

动态化的难点在设计，不在代码：先把机制想清楚，再实现。

1. 写 `设计书.md`：改造定位、要做的动态轴、每条轴的变量草图、哪些现有条目可以接进机制
2. 逐块和女主角定稿，每块一个停点；标「待定」的地方不擅自补完
3. 定稿后按 `30` → `31` → `32` →（`33`）→ `34` 实现。建议先做一个**最小可玩切片**（一两条轴）打包实测，跑通再铺开

技术提醒：

- 随机掷骰、后台结算这类「只能发生一次」的逻辑放酒馆助手脚本（在 MVU 变量更新完成后执行），不放 EJS：EJS 每次组装提示词都会重新执行，重新生成 / 切换回复时会重复掷骰
- EJS 只负责读变量、按变量输出指令

### 5. 交付

照 `99_打包`。交付时附一份和原卡的比对摘要（`diff_card.js` 输出），让女主角知道改了什么。
