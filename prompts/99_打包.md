# 99 打包

把 `works/<作品>/` 下的产物打包成可导入 SillyTavern 的 PNG 角色卡。完全离线，不连酒馆。

| 项 | 内容 |
|---|---|
| 前置 | `90_自检` 全量自检通过，必停点 ⑥ 女主角已确认 |
| 产物 | `works/<作品>/dist/<卡名>.png`（不进 git） |

## 步骤

### 1. 头像

`works/<作品>/头像.png` 必须存在。缺少头像时 tavern_sync 输出的是 JSON 文本，扩展名却是 `.png`，酒馆无法导入。

女主角没有提供头像时，先生成占位图，并提醒她导入前替换：

```bash
node scripts/placeholder_avatar.js works/<作品>/头像.png
```

### 2. index.yaml

第一次打包时，从 `templates/index-template.yaml` 复制到 `works/<作品>/index.yaml`；之前各模块已经追加过条目的，只核对。

核对清单：

- [ ] `第一条消息` 列出了 `第一条消息/` 下的全部文件，顺序正确（第一个是 `first_mes`，其余为备选开场）
- [ ] `世界书/` 下每个要进卡的文件都有一个条目，`文件:` 路径不带扩展名
- [ ] 每个条目都写了递归设置（见下）
- [ ] 绿灯条目都有 `关键字`
- [ ] 女主角人设默认不进卡（见 `13_捏人-user人设`）
- [ ] 主角色按 CARD_CONFIG 的「主角色入卡」处理（见下）
- [ ] 有角色列表时，列表里每个姓名都是对应绿灯条目的关键字

**主角色入卡**：

- 放角色描述的那一位：每次打包前都运行一次（只接受一个档案）

  ```bash
  node scripts/fill_description.js works/<作品> 角色/角色-甲.txt
  ```

- 放世界书的：确认 `index.yaml` 里每位都有条目，文件指向 `角色/角色-<名>`

**启用了 MVU 时**：

- 每次打包前同步变量结构脚本：

  ```bash
  node scripts/fill_script.js works/<作品> 变量结构 MVU/变量结构.js
  ```

- 做了 `34_MVU5-状态栏` 的，「[界面]状态栏」正则是 `启用: true`
- `[initvar]变量初始化勿开` 保持 `启用: false`
- CARD_CONFIG「MVU 变量更新显示」选了折叠显示的，`扩展字段.正则` 里是 `templates/index-MVU折叠正则.yaml` 的三条，没有「不发送&隐藏变量更新」

**递归默认值**：所有条目都写

```yaml
    递归:
      不可被其他条目激活: true
      不可激活其他条目: true
```

否则条目之间会网状互相激活，token 暴涨。只有女主角明确要求、并且清楚后果时才去掉。

### 3. 登记打包配置

在 `tools/tavern_sync.yaml` 的 `配置:` 下追加：

```yaml
  <作品>:
    类型: 角色卡
    酒馆中的名称: <卡名>
    本地文件路径: ../works/<作品>/index
    导出文件路径: ../works/<作品>/dist/<卡名>
```

`导出文件路径` 不要写扩展名，工具会自动加 `.png`。

### 4. 打包

```bash
node tools/tavern_sync.mjs bundle <作品>
```

### 5. 验证

```bash
node scripts/inspect_card.js works/<作品>/dist/<卡名>.png
```

核对输出里的开场白数量、世界书条目数量与蓝灯 / 绿灯、正则、酒馆助手脚本，与 `index.yaml` 一致；脚本显示「内容为空」说明漏了 `fill_script.js`。

### 6. 交付

告诉女主角：

1. 卡文件路径
2. 导入方法：酒馆 → 角色管理 → 导入角色卡，选这个 PNG
3. 不在卡里、需要她手动处理的东西：女主角人设（粘到用户设定）、头像是否为占位图、`附件/` 下的内容
4. CARD_CONFIG「需要的扩展」不是「无」时：列出要装的扩展（见 AGENTS.md「玩家需要的扩展」），并提醒导入卡时允许运行卡内脚本
5. 更新 `进度.md`，标记打包完成和版本号
