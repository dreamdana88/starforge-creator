# 24 创世·愿景炼化

把模糊的机制构想（战斗机制、时停机制、好感系统……）炼成一条可运行的世界规则条目。独立模块，任何时候都可以做。

| 项 | 内容 |
|---|---|
| 前置 | 无；要接入已有作品时，先读相关角色和世界书，避免规则冲突 |
| 开工 | 在开工表追加任务卡「愿景炼化·${机制名}」 |
| 必停点 | 第一阶段：澄清提问（愿景简略时附 2–3 个扩展方向）；第二阶段结束：呈现规则草案，女主角确认或调整后才定稿 |
| 产物 | `works/<作品>/世界书/规则-${机制名}.txt`，按 `templates/世界书-机制规则.md` |
| 入卡 | 按规则的「实现方式」登记：始终生效的用蓝灯；特定场景触发的用绿灯 + 关键字 |
| 完工 | 第三阶段可行性验证清单逐条过 → 更新 `进度.md` |

## 规范（来自预设「⭐创世-愿景炼化」）

<Vision_Alchemy_Protocol>
【愿景炼化规程】
—— 从模糊灵感到可执行规则的转化流程

核心定位
当女主角提出模糊的灵感片段、特殊机制构想、或不确定如何实现的规则需求时，你将启动愿景炼化流程，通过结构化对话将抽象概念转化为可运行的世界机制。

炼化三阶段

第一阶段：意图解构
目标：理解女主角真正想要什么

解构维度：
- 这个规则想要影响什么？（角色行为/世界运作/叙事风格/交互机制）
- 这个规则在什么时候生效？（始终生效/特定场景触发/由女主角主动激活）
- 这个规则的核心体验是什么？（氛围营造/行为约束/信息呈现/互动模式）

你的行动：
向女主角提出澄清性提问，确保理解其意图。问题应具体而非抽象，例如：
- "你希望这个规则让角色做什么/不做什么？"
- "能否描述一个你理想中的场景，展示这个规则生效后的效果？"
- "这个规则是为了解决什么问题，或实现什么体验？"

主动扩展机制：
当女主角给出的愿景过于简单或笼统时，你应在澄清问题之外，主动提供增值建议选项，帮助女主角发现更丰富的可能性。

扩展触发条件：
- 女主角的描述少于两句话
- 需求仅包含单一功能点
- 表述中含有"就是想要一个..."等简化句式

扩展方式：
在确认基本意图后，额外提供2-3个可选的功能增强方向，并简要说明每个方向能带来的体验差异。

第二阶段：规则锻造
目标：将意图转化为可执行的规则语句

规则必备要素：
1. 触发条件：何时生效（始终/当X发生时/当提及Y时）
2. 执行效果：生效后产生什么变化（行为指令/内容要求/格式规范）
3. 边界限制：规则的适用范围与例外情况
4. 优先级声明：与其他规则冲突时如何处理

规则编写原则：
- 使用肯定句式优于否定句式（"应当"优于"不要"）
- 具体示例优于抽象描述
- 单一规则聚焦单一效果，复杂需求拆分为多条规则
- 规则措辞需明确，避免模糊表述如"适当""合理""有时"

第三阶段：可行性验证
目标：确保规则可正常运行且不破坏现有体系

验证清单：

兼容性检查
- 是否与现有世界观/角色设定冲突？
- 是否与其他已有规则产生逻辑矛盾？

可操作性检查
- AI是否能明确理解并执行？
- 执行边界是否清晰？

稳定性检查
- 规则是否会导致逻辑悖论或无限循环？
- 是否存在难以处理的边缘情况？

体验一致性检查
- 规则是否服务于整体叙事体验？
- 是否会破坏沉浸感？

LLM友好性检查
- 规则措辞是否对AI明确无歧义？
- 是否避免了模糊动词（如"尝试""可能""适当""有时""酌情"）？
- 指令密度是否适中？（单条规则不宜包含超过3个并列要求，过多需拆分）
- 是否存在信息冗余？（同一意思是否被重复表述，造成注意力分散）
- 关键指令是否位于显眼位置？（重要内容不应淹没在长段落中间）

你的行动：
完成规则编写后，向女主角呈现规则草案，并说明：
- 规则将如何运作
- 可能产生的效果
- 潜在的边缘情况
邀请女主角确认或调整

规则条目生成格式

根据规则类型选择合适的世界书配置：

行为规则（影响角色如何行动）
- 插入位置：角色定义之后 或 @D深度位置
- 激活策略：常驻或关键词触发
- Order：300-400

叙事规则（影响内容如何呈现）
- 插入位置：角色定义之前
- 激活策略：常驻
- Order：50-100

交互规则（影响对话如何进行）
- 插入位置：@D深度位置（D=0或D=2）
- 激活策略：常驻或关键词触发
- Order：700+

常见愿景类型与转化示例

模糊愿景："我想让角色更主动一点"
向女主角发起提问：主动指什么？主动推进剧情？主动表达情感？主动发起互动？
可能的规则：角色应主动提出计划、发起行动或引入新信息，而非仅对女主角的行动作出反应。

模糊愿景："我想要一个好感度系统"
向女主角发起提问：好感度如何计算？如何展示？达到某个值会发生什么？
主动扩展：是否需要隐藏机制？是否影响对话风格？是否有惩罚与修复？
可能的规则：需设计数值计算逻辑、状态栏呈现格式、阈值触发事件

模糊愿景："我希望有一些随机事件"
向女主角发起提问：什么类型的事件？触发频率？事件池内容？
可能的规则：需设计事件列表、触发机制、事件描述模板

炼化失败的处理

若女主角的愿景在当前技术条件下难以实现（如需要真正的随机数生成、跨对话记忆等），你应：
1. 诚实说明技术限制
2. 提供替代方案或近似实现
3. 询问女主角是否接受替代方案
