# 10 捏人·主角色

| 项 | 内容 |
|---|---|
| 前置 | `00_开工` 完成（开工表作品总表已填）；有女主角人设时一并读取 |
| 开工 | 读开工表、CARD_CONFIG 启用的 `rules/`、已有的 `角色/` 与 `世界书/`；在开工表追加任务卡「主角色·${角色名}」 |
| 必停点 | **③ 角色定稿**：先只给出 `Core` 判词、1–3 条关键经历、`About_user` 四项摘要，女主角确认后再写全档 |
| 产物 | `works/<作品>/角色/角色-${角色名}.txt`，按 `templates/角色-主角色.md` |
| 入卡 | 按 CARD_CONFIG 的「主角色入卡位置」，见下方 |
| 完工 | 按 `90_自检` 的「角色」项自检 → 更新 `进度.md` → 告诉女主角下一句短指令 |

多个主角色时，一个一个来：每个角色都单独过一次必停点③。

### 入卡位置

CARD_CONFIG 的「主角色入卡」还没定时，开工前先问女主角。角色描述栏只放一个角色，**不要把多个角色拼进角色描述**。

**只有一个主角色**：默认放角色描述；女主角习惯放世界书时按她的来。

**有多个主角色**：必须问女主角，给出两个方案：

| 方案 | 做法 |
|---|---|
| A. 挑一个放角色描述 | 女主角指定一位放角色描述，其余主角色放世界书 |
| B. 全部放世界书（推荐） | 所有主角色都放世界书 |

放世界书的主角色推荐用**绿灯**，并提醒女主角配套使用 `12_捏人-角色列表` 模式 A：生成一条蓝灯常驻的角色索引，演出 AI 始终知道有哪些角色；对话提到谁，再触发谁的完整档案。需要一直在场的角色才用蓝灯。

具体做法：

- 角色描述：不登记世界书条目；打包前由 `scripts/fill_description.js` 把这一位的档案填进 `index.yaml` 的 `角色描述`
- 世界书绿灯：`index.yaml` 追加条目，绿灯，角色定义之后，顺序 300 起，关键字 = 姓名 + 称号 / 昵称（与角色列表里的姓名一致），文件 `角色/角色-${角色名}`
- 世界书蓝灯：同上，但不需要关键字
