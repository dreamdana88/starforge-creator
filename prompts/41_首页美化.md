# 41 首页美化

给角色卡做一个可交互的介绍首页：它占第一条开场白（swipe[0]），玩家点开场白入口直接跳到对应开场，每条开场白顶部有「返回介绍」按钮。

| 项 | 内容 |
|---|---|
| 前置 | 开场白已定稿（`22_创世-开场白`）；有发布介绍（`28`）时直接复用其中的标题、标签、简介、避雷 |
| 开工 | 在开工表追加任务卡「首页美化」；告诉女主角：首页要求玩家安装**酒馆助手**，写进 CARD_CONFIG「需要的扩展」 |
| 必停点 | 先确认：要展示哪些字段（含自定义字段）、视觉风格（按世界观给 2–3 个建议）、可选增强（头像 / 开场配图 / BGM）、作者与「碎碎念」内容（碎碎念必须问女主角，不代写） |
| 产物 | `第一条消息/首页.txt`（只有 `<CardIntro>` 数据）；其余每个开场白文件末尾加一行 `<BackToIntro/>`；`美化/首页.html`、`美化/返回按钮.html`（从 `templates/首页/` 复制后定制，**第一行和最后一行是三个反引号**） |
| 入卡 | 把 `templates/index-首页片段.yaml` 合并进 `index.yaml`：`第一条消息` 列表首页放第一个；三条正则 |
| 完工 | 按下方「生成自查」逐项核验 → 更新 `进度.md` |

与预设原文的差异：

- 开场白文件由你直接改，`<BackToIntro/>` 不需要女主角手动添加
- 正则随卡打包，不需要女主角手动建；HTML 写进文件并用三个反引号包住（酒馆助手只渲染代码块里的完整 HTML）
- 工坊补充第三条正则「[不发送]返回按钮标记」：不把 `<BackToIntro/>` 发给 AI，防止 AI 模仿着在回复末尾也写一个
- `[开场]` 的 id 就是开场白在 `第一条消息` 列表里的位置：首页是 0，第一条开场白是 1

## 规范（来自预设「⭐创世-首页美化」）

<CardIntro_Protocol>
【开场首页美化生成规范】

功能定位：
为角色卡 swipe[0] 生成一个可交互的介绍首页，集中展示角色卡全貌（标题、标签、角色档案、开场白入口等），玩家点击开场白入口后直接跳转到对应 swipe，无需使用原生翻页 UI。每个开场白 swipe 同时嵌入「返回介绍」按钮，支持逆向导航。

核心机制：
- 角色卡局部正则（AI 输出 + 仅格式显示）
- 正则A 替换 swipe[0] 中的 <CardIntro> 块 → 介绍首页 HTML（跳转由 JS 调用 setChatMessages 实现）
- 正则B 替换各开场白 swipe 末尾的 <BackToIntro/> 标记 → 返回按钮 HTML
- 开场白数量动态解析，增减 [开场] 块即可，正则本身永远不需要改

## 一、CardIntro 数据格式规范

### swipe[0] 内容格式

写入 `第一条消息/首页.txt`，**首尾不添加其他正文**：

```
<CardIntro>
[标题]角色全名[/标题]
[副标题]一句话钩子/台词/核心矛盾，30字内[/副标题]
[标签]标签1,标签2,标签3（5-8个，逗号分隔）[/标签]

[简介]
2-4句话概括整体风格、剧情基调、核心体验，100字内。
[/简介]

[角色]
name: 角色名
quote: 核心台词，体现性格或张力
[desc]
角色个人简介。侧重性格、外貌魅力以及对 {{user}} 的态度。
可多行。
[/desc]
[/角色]

[避雷]敏感内容提示，如无则写：无特殊雷点[/避雷]
[作者]作者名[/作者]
[碎碎念]作者想说的话（内容需询问女主角）[/碎碎念]

[开场]
id: 1
title: 开场白标题，10字内
desc: 一句话概括氛围/场景，20字内
img: https://图片URL（可选，有则渲染为图片卡，无则纯文字卡）
[/开场]

[开场]
id: 2
title: 第二个开场白
desc: 概括
[/开场]

（按实际开场白数量重复 [开场]…[/开场]）
（id 字段的值即该开场白的 swipe_id：swipe[0] 已被介绍首页占用，故第一条开场白 id 必须为 1，以此类推）
</CardIntro>
```

**字段说明（均为可选，按女主角愿景按需生成）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| [标题] | 单标签 | 角色全名或卡名 |
| [副标题] | 单标签 | 一句话钩子或台词 |
| [标签] | 单标签 | 逗号分隔的标签列表 |
| [简介] | 块标签 | 多行概括文字 |
| [角色] | 块标签 | 角色档案，可有多个（多角色卡重复此块）|
| [避雷] | 单标签 | 避雷提示 |
| [作者] | 单标签 | 作者署名 |
| [碎碎念] | 单标签 | 作者附言 |
| [开场] | 块标签 | 开场白条目，必须有 id 字段；img 可选 |

**[角色] 块内部字段：**
- `name:` 角色名（单行）
- `quote:` 核心台词（单行）
- `[desc]...[/desc]` 角色描述（多行块）

**多角色卡示例：**
```
[角色]
name: 角色A
quote: 台词A
[desc]描述A[/desc]
[/角色]

[角色]
name: 角色B
quote: 台词B
[desc]描述B[/desc]
[/角色]
```

## 三、HTML 结构模板

### 结构A：介绍首页

模板：`templates/首页/首页.html`。结构分为两部分：
- **固定部分**（注释标注「固定」）：数据解析逻辑 + 跳转绑定，不得修改
- **定制部分**（注释标注「定制」）：CSS 样式 + HTML 构建，根据女主角愿景，综合参考角色设定与世界观进行发挥

跳转绑定规则：所有可点击的开场白元素**必须带有 `data-swipe-to="N"` 属性**（N = 对应 swipe_id），JS 会自动绑定点击事件。

字段解析要点（模板注释里也有）：
- 按本次 CardIntro 实际包含的字段调用 `extract('字段名', raw)`，任意自定义字段均可（如 `extract('能力体系', raw)`）
- 未填写的字段 extract 返回 ''，构建 HTML 时判断为空再决定是否渲染
- HTML/JS 中不硬编码任何具体值（角色名、型号、配置文字等）：想展示的信息，先在 `<CardIntro>` 数据里加对应 [字段名] 标签，再用 extract() 读取；数据里没有的字段，一律静默跳过，不得自行填充
- 单人卡（characters.length === 1）：默认调用 getCharAvatarPath('current') 获取头像，渲染在角色档案区
- 多人卡/大世界卡（characters.length > 1 或无 [角色] 块）：不自动调用头像，按女主角需求决定

### 结构B：返回按钮

模板：`templates/首页/返回按钮.html`。建议小胶囊形，色系与介绍首页呼应。

## 四、美学规范

所有美化代码的编写，都需遵循「工坊美学」——在强调艺术性的同时，恪守阅读的舒适度。综合女主角愿景与角色世界观自由选择、创新组合，以下各项均为参考示例而非限制。

---

**【硬性规范 — 不可违背】**
- 字色与背景须满足 WCAG AA 对比度（浅底深字或深底浅字，确保清晰可读）
- 拒绝高饱和度刺眼撞色；禁止频闪或强光耀效果，光效应柔和
- 必须适配移动端与桌面端，手机竖屏下内容自动折行/堆叠，禁止横向溢出
- `body` 必须设置 `margin: 0; padding: 0;`
- `.ci-wrap` 必须设置 `width: 100%; box-sizing: border-box;`，**严禁**设置 `max-width` 固定值或 `margin: 0 auto`（会导致页面窄居中，破坏门面效果）
- 高度由内容自然撑开，**严禁**设置固定高度

---

**【设计风格 参考— 按质感分组，包括但不限于，可跨组混搭】**

轻盈透明系（现代/恋爱/清新向）：
Glassmorphism / Soft UI / Luminism / Watercolor Style / Pastel Flat / Frosted Card

立体肌理系（可爱/奇幻/治愈向）：
Claymorphism / Neumorphism / Papercraft Style / Paper Cut Art / Embossed Relief / Bubble UI

扁平极简系（都市/职场/冷感向）：
Minimalism / Flat Design / Material Design / Line Art Style / Swiss Style / Editorial Layout

沉浸暗调系（悬疑/末日/病娇/克苏鲁向）：
Dark Neumorphism / Gothic UI / Terminal Style / Cyberpunk Dark / Noir / Brutalism

手工复古系（民国/复古/田园/文艺向）：
Scrapbook Style / Letterpress / Risograph Print / Typewriter Old Paper / Collage Art / Zine Style

东方美学系（古风/仙侠/江湖/宫廷向）：
Ink Wash Style（水墨）/ Washi Paper（和纸）/ Traditional Pattern（锦纹）/ Ukiyo-e Inspired / Seal & Stamp / Classical Scroll

世界观参考（建议起点，仅作参考）：
- 古风/仙侠 → 东方美学系 + 手工复古系
- 现代/都市 → 轻盈透明系 + 扁平极简系
- 赛博/科幻 → 沉浸暗调系 + 扁平极简系
- 西幻/宫廷 → 立体肌理系 + 手工复古系

**【配色方案 — 包括但不限于】**
可选配色（包括但不限于）：
Pastel colors / Monochrome / Gradient colors / Vintage colors / Nature colors /
Dark mode / Neon colors / Jewel tones / Earth tones / Sakura palette /
Aurora colors / Ocean depth / Macaroon colors / Wabi-sabi neutral /
Ink & Paper / Sunset gradient / Crystal clear / High contrast

原则：色彩须与世界观契合；推荐低饱和优雅渐变或半透明磨砂质感；禁止大面积高饱和原色。

**【标题与版块样式 — 包括但不限于】**
可选标题样式（包括但不限于）：
Tag-style / Left Border Title / Underline Title / Icon Title /
Shadow Title / Decorative Shape Title / Full-width Background Title /
Divider Title / Stamp Style / Washi Tape Label / Ribbon Banner /
Torn Paper Edge / Neon Sign / Crystal Badge / Postmark Style / Handwritten Brush

鼓励为不同层级信息选用不同样式，增强视觉层次感。

**【装饰元素 — 包括但不限于】**
可叠加（包括但不限于）：
分割线、胶囊/卡片区块、对话气泡、渐变叠加层、SVG 装饰纹样、角标、边框光泽、背景水印、
浮动粒子、星座点阵、胶片颗粒感（Film Grain）、噪点纹理、散落花瓣/星屑、
蜡封印章、邮戳、Tarot 边框、月相/星象图案、镂空剪纸

**【动效规范】**
- 页面载入：淡入（fade-in）或上浮（slide-up）
- 开场白入口：必须有 hover 反馈（颜色/位移/阴影变化均可）
- 图片卡：可加 CSS @keyframes 晃动/漂浮动画
- 进度条/数值变化：平滑过渡（transition）
- 禁止大量频闪或强烈闪光

---

**【CSS 编写规范】**
- 所有类名使用 `ci-` 前缀，避免污染酒馆原生样式
- 禁止使用 `vh` 单位，改用百分比或 Flex/Grid 控制布局
- 禁止 `//` 单行注释，仅使用 `/* */` 格式
- 禁止从外部 URL import 字体或模块（可使用系统字体栈或 Google Fonts `@import` 在 `<style>` 内声明）

## 五、可选增强功能（函数参考）

以下功能均为可选，女主角有需求时在生成时调用对应接口：

### 角色头像

```javascript
/* 获取当前角色头像路径，返回如 "/characters/xxx.png" */
var avatarPath = getCharAvatarPath('current');
/* 示例：渲染为圆形头像 */
/* <img src="' + avatarPath + '" style="border-radius:50%;width:80px;"> */
```

适用场景：单人卡推荐放在角色档案区；多人卡/大世界卡可按需决定是否使用。

### 开场白配图

在 `[开场]` 块中加入可选的 `img:` 字段（图片 URL），结构 A 的 JS 已自动解析到 `opening.img`：

```javascript
/* 在 HTML 构建部分判断是否有图 */
if (opening.img) {
  /* 渲染图片卡：背景图 + 标题 + 描述 */
  /* 可加 CSS @keyframes 晃动/漂浮/渐变等适配风格的动画 */
} else {
  /* 渲染纯文字卡：标题 + 描述 */
}
```

### BGM 播放（切换按钮）

```javascript
/* 在 CardIntro 数据中加 [bgm] 字段存放音频 URL，可选 */
var bgmUrl   = extract('bgm',   raw);
var bgmTitle = extract('bgm标题', raw);  /* 可选 */

/* 切换播放/暂停 */
function toggleBgm() {
  var audio = getCurrentAudio('bgm');
  if (audio.playing) {
    pauseAudio('bgm');
  } else {
    playAudio('bgm', { url: bgmUrl, title: bgmTitle || 'BGM' });
  }
}

/* 对应的 HTML 按钮 */
/* <button id="ci-bgm-btn" onclick="toggleBgm()">♪</button> */
```

其他音频控制接口：
- `getAudioList('bgm')` 获取播放列表
- `replaceAudioList('bgm', [{url, title}])` 替换播放列表
- `setAudioSettings('bgm', { mode: 'repeat_one', volume: 80 })` 设置模式/音量
- `type` 可为 `'bgm'`（背景音乐）或 `'ambient'`（音效）

## 六、生成自查

生成完成后请逐项核验：

1. **swipe[0]**（`第一条消息/首页.txt`）内容仅含 `<CardIntro>…</CardIntro>`，不附加其他正文；它在 `index.yaml` 的 `第一条消息` 列表里排第一
2. **swipe[1+]** 每条开场白正文末尾有 `<BackToIntro/>`
3. `[开场]` 块的 **id 值 = swipe_id**（swipe[0] 已被介绍首页占用，第一条开场白 id 必须为 1）
4. 结构 A 的 HTML 中，每个开场白入口元素**带有 `data-swipe-to` 属性**
5. CSS 中 `.ci-raw` 设置了 `display: none`
6. JS/HTML 中无硬编码具体值，所有内容来自 `extract()` 或解析变量
7. 无 `//` 单行注释，无外部 import 语句
8. 正则B 替换的按钮 HTML 尺寸紧凑，不过度撑高 iframe
9. 两个 HTML 文件第一行和最后一行是三个反引号；三条正则都已合并进 `index.yaml`
