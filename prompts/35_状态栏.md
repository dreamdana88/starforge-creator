# 35 状态栏（不用 MVU）

靠世界书指令 + 正则实现的状态栏：AI 每轮按格式输出状态块，正则把它替换成文字或美化界面。要用变量系统的，走 `30`–`34` MVU 流程。

| 项 | 内容 |
|---|---|
| 前置 | 角色、世界书已基本定稿；开工时先读知识库 `references/状态栏.md`，做带交互的高级美化时再读 `references/高级美化.md` 与 `references/正则.md` |
| 开工 | 在开工表追加任务卡「状态栏」 |
| 必停点 | 下方规范「交互流程」三项（内容维度、纯文字 / 美化、视觉风格）都要先问，不直接套模板 |
| 产物 | `世界书/状态栏-${名称}.txt`（输出格式指令）；美化版另有 `附件/状态栏-${名称}.html`（第一行和最后一行是三个反引号）；`附件/状态栏-测试文本.txt`（供女主角粘贴验证） |
| 入卡 | 世界书条目：指定深度 1 或 0，顺序 700+，常驻或关键字；正则写进 `index.yaml` 的 `扩展字段.正则`，美化版用 `文件:` 指向 HTML |
| 完工 | 检查正则能精确匹配输出模板、CSS 类名带独特前缀、手机竖屏不出现横向滚动 → 更新 `进度.md` |

## 规范（来自预设「⭐创世-状态栏」）

<StatusBlock_Protocol>
【状态栏构建协议】

一、 功能定位
状态栏是剧场的“第二舞台”，它以数据可视化的形式锚定当前场景的核心变量。它不仅是维持叙事逻辑的船锚，更是增强沉浸感的视觉窗口。它负责将抽象的“状态”具象化，让女主角能直观感受到角色的每一次心跳与世界的每一次呼吸。

二、 交互流程：定制咨询
当女主角提出生成状态栏或美化界面的需求时，不得直接输出通用模板。必须启动“定制咨询”程序，或基于对剧本的深刻理解提出主动建议。

1.  内容维度的确认
询问：您希望追踪哪些信息？是侧重**角色状态**（服装/动作/心态/心声/好感），还是**世界信息**（时间/天气/地点/事件进程），亦或是**带有交互的高级美化页面**？
建议：若女主角未指定，应根据剧本类型推荐。如恋爱剧推荐“好感+心声”组合；冒险剧推荐“生命值+装备”组合。

2.  形式与模式的选择
询问：您偏好**纯文字版**（简洁/兼容性高）还是**美化版**（视觉丰富/沉浸感强）？
询问：若是美化版，根据角色数量选择**静态轻量版**（单人/固定）还是**动态全栈版**（多人/自适应）？
建议：若角色卡涉及多名可攻略角色，务必推荐**动态全栈版**以支持群像互动。

3.  视觉风格的定调
原则：UI风格必须是角色灵魂的延伸。严禁使用千篇一律的通用模板。
适配举例（鼓励创新）：
古风/仙侠：水墨晕染、云纹边框、衬线字体、竖排排版。
现代/都市：玻璃拟态（Glassmorphism）、极简线条、柔和阴影、无衬线字体。
赛博/科幻：全息投影感、霓虹柔光、数据流动效、科技感切角。
西幻/宫廷：羊皮纸质感、金属蚀刻纹样、古典花体、宝石镶嵌元素。

三、 美学规范：女性向UI设计准则
所有美化代码的编写，都需遵循“工坊美学”——在强调艺术性的同时，恪守阅读的舒适度。

1.  视觉体验
色彩：拒绝高饱和度的刺眼撞色。推荐使用低饱和度的莫兰迪色系、优雅的渐变色或半透明的磨砂质、清新可爱的糖果色系等。字体颜色必须与背景形成足够对比度（WCAG AA标准），确保清晰可读。
光影：避免大量频闪或强烈的光耀效果。光效应当是柔和的呼吸灯或流光，而非刺眼的闪光灯。
布局：必须适配**移动端**与**电脑端**。在手机竖屏下，内容应自动折行或堆叠，严禁出现横向滚动条或文字溢出。

2.  装饰细节（CSS Magic）
鼓励使用CSS3特性增强精致感：
边框：细致的1px边框，可带有微弱的渐变光泽。
圆角：根据风格选择圆润（现代/可爱）或锐利（冷峻/科技）。
纹样：使用SVG或Unicode字符作为背景水印或角标装饰。
动效：新状态出现时应有淡入（Fade-in）或上浮（Slide-up）动画；进度条变化应有平滑过渡（Transition）；交互元素应有按压反馈。

**四、 输出规范：严谨的交付物**
需仔细学习并理解`references/状态栏.md`以及高级扩展`references/高级美化.md`技术指南后生成

美化版的最终交付必须严格包含以下四个部分：
1.  **世界书规范 (World Info Rules)**
正文输出位置（推荐回复末尾）、世界书设置（推荐插入位置：**聊天深度 ⚙ D1/D0 **, 插入顺序:700+）。
提供严格的输出模板（XML标签或特定分隔符），确保AI生成的数据结构稳定。

格式：|
```xml
条目名称：
关键词：
插入位置：${推荐⚙ D1/D0}
插入顺序：${数字：推荐700+}
激活策略：${常驻/关键词：推荐关键词激活}
<状态栏名称占位符>
条目内容：${状态栏生成规范}
</状态栏名称占位符> （标签名根据条目内容生成中文/英文）
```

2.  **正则表达式 (Regex)**
提供精确匹配上述模板的正则表达式。
推荐设置为“仅格式显示”并勾选“AI输出”。
写进 `index.yaml` 的 `扩展字段.正则`，随卡打包；替换内容用 `内容:`，美化版用 `文件:` 指向 HTML（`替换为` 已弃用）。

3.  **完整美化代码 (HTML/CSS/JS)**
结构：美化版必须包含 `<!DOCTYPE html>`、`<html>`、`<body>` 完整标签结构。
样式前置：`<style>` 标签必须紧跟 `<body>` 之后，位于所有HTML元素之前，确保样式优先加载。
逻辑：动态版的脚本必须置于 `</body>` 之前或包裹在 `DOMContentLoaded` 监听器中。
隔离：所有CSS类名必须添加独特前缀（如 `cosmos-`），避免污染酒馆原生样式。
数据：动态版必须采用"隐藏容器存储数据 + JS读取渲染"的模式。
适配：界面显示在 iframe 里——不用 vh 等受宿主高度影响的单位（用 width + aspect-ratio）；不用 min-height、overflow: auto 强制撑高；主体不用 position: absolute；不出现横向滚动条。

4.  **使用说明与测试**
世界书条目和正则都随卡打包，女主角不需要手动配置；交付时说明卡里加了哪些条目和正则。
必须输出一段测试文本：包含完整的标签结构和模拟内容，供女主角复制粘贴到AI回复的聊天框中验证效果。

</StatusBlock_Protocol>
