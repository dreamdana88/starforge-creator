SillyTavern 状态栏（Status Block）技术指南

#### 一、 什么是状态栏
状态栏是SillyTavern中用于维持角色扮演一致性与增强沉浸感的辅助工具。它通常表现为一段附加在AI回复末尾（或开头）的结构化文本，用于实时追踪和展示当前场景的关键变量。世界书指令条目推荐 插入位置：聊天深度 ⚙ D1/D0，插入顺序：700+

#### 二、 基础篇：文字状态栏 (Text Status Block)

定义：直接以纯文本或Markdown格式显示的状态信息。
特点：只依赖世界书（World Info）或预设指令生成，无需额外插件，信息对用户与AI双向可见。
优势：配置简单，兼容性强，有助于AI保持上下文记忆。

*   **示例（内容可根据女主角愿景调整）**：
    以下模板使用了HTML折叠标签，可避免状态栏占用过多屏幕空间。

    <StatusBlock>
    <details><summary>角色状态 {角色名称}</summary>
    ```
     👗服装: {角色当前穿着的服装}
     💃动作: {角色当前的动作或姿态}
     👁心态: {当前心态/情绪}
     🗨心声: {第一人称内心想法，30字内}
     ❤好感度: {当前好感度数值}/100
    ```
    </details>
    </StatusBlock>

指令规范：
    1.  触发机制：状态栏必须根据剧情发展实时更新。
    2.  内容约束：心声（🗨）必须使用第一人称，严格控制字数。
    3.  输出位置：必须确保状态栏是回复内容的最后一个元素。


#### 三、 进阶篇：美化状态栏 (Beautified Status Block)

美化状态栏利用正则表达式（Regex）脚本，将AI生成的特定格式文本拦截并替换为HTML/CSS渲染的图形界面。根据实现原理与适用场景，分为**静态版**与**动态版**。
 一个完整可用的美化状态栏系统由以下三个部分组成：

1.  **世界书生成规则 (World Info Generation Rules)**
    职能：作为"蓝图"，指导生成数据。
    要求：必须定义明确的数据结构（如特定分隔符），必须包含包裹标签（如 `<Status>...</Status>`），严禁包含注释。

2.  **美化代码 (HTML/CSS/JS)**
    职能：作为"皮肤"，负责数据的视觉渲染。
    机制：代码被嵌入在正则表达式的"替换"字段中，利用正则捕获组（如 `$1`）获取生成的原始数据并进行展示。

3.  **正则表达式 (Regular Expression)**
    职能：作为"桥梁"，连接输出内容与美化代码。
    内容：精确匹配世界书规则中定义的包裹标签及其内部内容，通常设置勾选为"AI输出""仅格式显示"。

#### 四、 通用结构规范

无论静态版还是动态版，美化代码都必须遵循以下结构规范，以确保在SillyTavern环境中正确渲染：

1.  **完整HTML文档骨架**：必须包含 `<!DOCTYPE html>`、`<html>`、`<body>` 标签作为最外层包裹。
2.  **样式前置原则**：`<style>` 标签必须置于所有HTML元素之前（紧跟 `<body>` 之后），确保样式在DOM渲染前加载。
3.  **闭合完整性**：`</body></html>` 必须作为代码的结尾。

标准结构模板：
```html
<!DOCTYPE html>
<html lang="zh-CN">
<body>
<style>
/* 所有CSS样式写在这里 */
</style>

<!-- 所有HTML元素写在这里 -->
<div class="your-container">...</div>

</body>
</html>
```

### 方案 A：静态轻量版 (Static Mode)
**适用场景**：单人角色卡、生成条目固定、无需复杂逻辑处理的场景。
**核心原理**：利用正则表达式的"捕获组"直接提取数据，填入HTML模板。无需JavaScript参与。

#### 生成规则
1. 状态栏条目使用XML风格的开闭标签，确保正则捕获的精准度。
2. 正则表达式需精准定位每个标签内的内容，并启用占位符进行分配。
3. 将捕获的变量直接嵌入HTML结构中。

**完整示例（内容可根据女主角愿景调整）**：

**世界书规范**：
```
在每次回复的末尾，必须输出角色状态栏。严格遵循以下格式：

<StatusBlock>
<角色状态>{角色名称}</角色状态>
<服装>{当前穿着}</服装>
<动作>{当前动作或姿态}</动作>
<心态>{当前情绪状态}</心态>
<心声>{第一人称内心独白，30字内}</心声>
<好感度>{数值}</好感度>
</StatusBlock>
```

**正则表达式 (Regex)**：
```regex
/<StatusBlock>\s*<角色状态>\s*([\s\S]*?)\s*<\/角色状态>\s*<服装>\s*([\s\S]*?)\s*<\/服装>\s*<动作>\s*([\s\S]*?)\s*<\/动作>\s*<心态>\s*([\s\S]*?)\s*<\/心态>\s*<心声>\s*([\s\S]*?)\s*<\/心声>\s*<好感度>\s*(\d+)\s*<\/好感度>\s*<\/StatusBlock>/gi
```

**美化代码 (HTML/CSS)**：

```html
<!DOCTYPE html>
<html lang="zh-CN">
<body>
<style>
/* CSS样式代码略 */
.cosmos-single-card{padding:14px;background:rgba(25,20,35,.82);border-radius:10px;color:#e0dce6;font-size:13px}
/* ...其余样式... */
</style>
<div class="cosmos-single-card">
  <div class="cosmos-single-name">$1</div>
  <div class="cosmos-single-row"><span class="cosmos-single-key">字段A</span><span class="cosmos-single-val">$2</span></div>
  <!-- ...根据捕获组数量添加对应元素... -->
</div>
</body>
</html>
```

### 方案 B：动态全栈版 (Dynamic Mode)
**适用场景**：多角色群像剧、角色数量不固定、需要复杂布局（如网格自适应）的场景。
**核心原理**：利用JavaScript监听DOM加载事件，解析包含多个角色的原始数据块，动态生成DOM元素。

#### 生成规则
1. 使用块级标签包裹每个角色，结构需统一，便于脚本循环解析。
2. 一次性捕获整个状态栏大标签内容块，不进行细分提取。
3. 美化代码包含完整的HTML文档结构，利用 `DOMContentLoaded` 事件确保脚本在DOM就绪后执行。
4. `<StatusBlock>` 下内部分类条目使用 `[]`，不可使用 `<>` 括号，会影响JavaScript正常运作。

*   **示例（内容可根据女主角愿景调整）**：

**世界书规范**：
```
在每次回复的末尾，为所有在场角色输出状态栏。所有信息包裹在<StatusBlock>内。

<StatusBlock>
[角色]
名称: {角色A名称}
...
[/角色]

[角色]
名称: {角色B名称}
...
[/角色]
</StatusBlock>
```

**正则表达式 (Regex)**：
```regex
/<StatusBlock>([\s\S]*?)<\/StatusBlock>/gi
```

**美化代码 (HTML/CSS/JS)**：
```html
<!DOCTYPE html>
<html lang="zh-CN">
<body>
<style>
  .cosmos-raw-data { display: none; }
  .cosmos-stage { display: grid; grid-template-columns: repeat(auto-fill, minmax(250px, 1fr)); gap: 10px; }
  /* ...卡片与布局样式... */
</style>

<!-- 隐藏容器存储原始数据 -->
<div class="cosmos-raw-data">$1</div>
<!-- 展示容器 -->
<div class="cosmos-stage"></div>

<script>
document.addEventListener('DOMContentLoaded', function() {
  // 1. 获取原始数据
  var raw = document.querySelector('.cosmos-raw-data').textContent;
  // 2. 正则循环解析 [角色]...[/角色] 块
  // 3. 动态生成HTML并插入 cosmos-stage
});
</script>
</body>
</html>
```

#### 五、 核心注意事项与规范

1.  **方案选择**：
    - 若仅需显示当前对话对象的状态，**方案A** 响应更快，容错率更高。
    - 若场景涉及多人互动，必须使用 **方案B**，否则正则无法处理数量可变的捕获组。

2.  **代码结构**：
    - **美化版代码**都必须包含 `<!DOCTYPE html>`、`<html>`、`<body>` 完整标签结构。
    - `<style>` 标签必须紧跟 `<body>` 之后，位于所有HTML元素之前。
    - 动态版的 `<script>` 必须放在 `</body>` 之前，或使用 `DOMContentLoaded` 监听器。

3.  **样式隔离**：
    所有CSS类名建议添加独特前缀（如 `cosmos-`），防止与SillyTavern原本的界面样式发生冲突。

4.  **移动端适配**：
    无论哪种方案，CSS中都应使用百分比宽度或 Flex/Grid 布局，确保在手机竖屏模式下内容不会溢出屏幕。
    优先考虑美化带有可折叠功能，点击展开，尽可能减少空间占用。
